# M24: Chart Report — 口语化排盘报告

## 1. 目标

新增排盘口语化报告能力。用户在排盘后点击单一按钮，获得一份完整的中文口语化盘面报告。报告由多个文字块拼接而成，每个文字块对应一个盘面数据维度，专业术语优雅转译为口语化中文。

分两阶段交付：
- **阶段一（M24-WP1 ~ M24-WP4）**：内容生成。后端组装完整文字块集合，确保每个术语有口语化映射，所有块拼接为一份通顺报告。
- **阶段二（M24-WP5）**：排版美化。前端渲染报告，合理分段、留白、字体层级。

## 2. 依赖

- M3 chart-create：四柱排盘数据。
- M4 analysis-snapshot：五行/十神/藏干结构化指标、关系标记、敏感标记。
- M12 chart-detail：不可变命盘快照。
- M13 luck-cycles：大运方向、起运年龄、8 步大运干支。
- M21 deep-analysis：日主强弱（得令/得地/得势 + 0-10 评分）、格局初判（正官/七杀/财/印/食伤/建禄/月刃/杂）、用神建议。
- M16 前端三栏布局：报告入口可落在左侧起盘栏排盘按钮下方。

## 3. 范围

### 阶段一：内容生成

| Work Package | 内容 |

| Work Package | 内容 |

## 4. 文字块定义

每个文字块的专业术语 → 口语化映射，示例：

| 文字块 | 数据来源 | 术语转译示例 |
| --- | --- | --- |
| 命盘概览 | 四柱干支 | 「你的命盘四柱为甲辰年、丙子月、庚午日、辛巳时」 |
| 日主介绍 | 日干 + 五行 + 阴阳 | 「你的日主是庚金，庚为阳金，属强韧之金，如刀剑矿石」 |
| 强弱判断 | 得令/得地/得势 + 评分 | 「庚金生于子月，冬水正旺，金不得令。地支四柱中得 X 支生扶，天干得 Y 干帮扶。综合评分 Z/10，判定为偏弱」 |
| 五行分布 | element_metrics | 「命盘中木行偏旺，火行中和，土行偏弱，金行偏弱，水行偏强」 |
| 十神关系 | ten_god_metrics | 「年干甲木为偏财，月干丙火为七杀，时干辛金为劫财……」 |
| 藏干透出 | hidden_stem_metrics | 「年支辰中藏戊乙癸，戊土透出有力……」 |
| 格局初判 | pattern_name | 「月令透干推演，格局为七杀格」 |
| 用神参考 | useful_god_hints | 「日主偏弱，七杀当令，首选印星化杀生身，次取比劫帮扶。此为传统命理参考，非确定性建议」 |
| 大运走势 | luck_cycles | 「大运顺行，约 X 岁起运。第一步大运为丁丑（X-Y 岁），第二步……」 |

## 5. 非目标

- 不生成 PDF / 富格式文件（M22 已覆盖 JSON 导出）
- 不引入 AI / LLM 生成（全部硬编码模板）
- 不提供编辑报告功能
- 不提供报告分享 / 导出为此报告格式
- 不生成流年/流月报告
- 阶段一不做排版美化

## 6. 能力状态

| Capability | Before | After |
| --- | --- | --- |
| `chart-report` | 不存在 | restricted |

新增 restricted 能力，消耗已有 supported/restricted API。限制：
- 报告文案不得含疾病/死亡/法律/金融/关系确定性断言（LOCK-009）。
- 不得在前端声称报告具有预测准确性。
- 报告免责声明必须始终出现在报告首部。
- 报告内容仅基于当前命盘数据，不得推测未来事件。

## 7. 验证

```bash
cargo test                        # 含 chart-report 相关测试
npm run check                     # 前端语法 + 测试
# 浏览器检查：排盘后点击报告按钮，验证报告完整性和文案安全
```

## 8. 约束

- LOCK-006：不得通过前端文案承诺后端未实现能力。
- LOCK-009：不得把解释文案写成确定性断言。
- 报告生成逻辑必须在后端实现（Rust 硬编码模板），前端只负责渲染。
- `/api/charts/report` 返回结构含 `disclaimer`、`blocks[]`、`assembled_report` 三部分，前端组装时不得修改 block 文案。
